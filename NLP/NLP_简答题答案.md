## Q1 文本语料分析的常见检查项，及其对建模的指导意义

### 一、要检查什么

| 检查维度 | 具体做什么 | 典型方法 |
| --- | --- | --- |
| 语料规模 | 样本总量、总词量、每类样本量 | `len(data)`、类别计数 |
| 标签/类别分布 | 各类别数量、是否均衡、最长尾类占比 | `value_counts()`、柱状图 |
| 文本长度分布 | 字符数/词数的均值、分位数（50/90/95/99）、最大最小 | `describe()`、直方图、箱线图 |
| 词频与词表 | 高频词、停用词、出现 1 次的 hapax 词、OOV 率 | 词频统计、Zipf 曲线 |
| 重复与噪声 | 完全重复样本、近重复、乱码、HTML 标签、URL、表情、空白 | 去重、正则清洗 |
| 字符构成 | 中/英/数字/标点/生僻字占比，是否繁体、是否含错别字 | 字符集统计 |
| 标注质量 | 抽样人工核对、标注一致性、边界是否清晰 | 抽样审查 |
| 数据划分 | 训练/验证/测试划分比例、是否存在跨集泄漏（同文本重复出现） | 集合求交 |
| 编码与格式 | 文件编码（UTF-8/GBK）、换行符、字段缺失 | 读取测试 |

### 二、对建模的指导意义（把"发现"翻译成"决策"）

1. **长度分布 → 输入长度与截断策略**
   - 取 95 或 99 分位数作为 `max_len`，兼顾覆盖率与算力。
   - 长度差异大 → 考虑按长度分桶（bucketing）减少 padding 浪费。
   - 长文本分类 → 可选截断、层次模型、或直接上预训练模型（BERT 的 512 限制需要滑窗/截断）。

2. **类别分布 → 采样、损失与评估指标**
   - 不均衡 → 过采样/欠采样、`class_weight`、`WeightedRandomSampler`。
   - 评估指标改用 **宏平均 F1 / AUC / PR 曲线**，不能只看 accuracy（全猜多数类就能拿高分）。

3. **词频分布 → 词表与向量方案**
   - 设定 `min_freq`（如 2 或 3）过滤低频词，控制词表规模。
   - OOV 率高 → 考虑改用**字向量 / subword（BPE）/ 预训练词向量**。
   - 词表规模决定 Embedding 参数量（词表 × dim），直接影响过拟合风险。

4. **噪声与重复 → 清洗规则与数据增强**
   - 去重（尤其训练集与测试集去重，防泄漏）。
   - 制定清洗规则：去 HTML、归一全半角、统一大小写、处理连续空白。

5. **标注质量 → 效果上限**
   - 数据决定上限，模型只是逼近上限。噪声标签多时优先修数据，而不是堆模型。

6. **数据划分 → 泛化估计是否可信**
   - 分层抽样（stratified split）保持各类比例一致。
   - 同源/同用户的样本应按组划分（GroupKFold），避免泄漏。

## Q2 n-gram 的作用、生成 2-gram、batch 中句子长度不齐的处理

### 一、n-gram 的作用

n-gram 是长度为 n 的**连续**词（或字）序列。

- **弥补词袋模型丢失语序的缺陷**：词袋只知"有哪些词"，n-gram 还能表达"词的相邻关系"。
- **作为特征**：文本分类、情感分析中把 n-gram 当作特征（TF-IDF + n-gram 是经典强基线）。
- **语言模型**：n-gram LM 用前 n-1 个词预测下一个词（配合平滑：加一平滑、Kneser-Ney）。
- **其他用途**：拼写纠错、新词发现、机器翻译评估（BLEU 基于 n-gram 精确率）。
- **n 的权衡**：n 越大，上下文越丰富，但**数据稀疏**越严重、特征维度爆炸、参数越多 → 实践中常只用 1-gram + 2-gram，少数到 3-gram。

### 二、生成 2-gram（示例）

```python
def generate_ngrams(tokens, n=2):
    """tokens: 已分词的 list，如 ['我', '爱', '自然语言', '处理']"""
    return [tuple(tokens[i:i + n]) for i in range(len(tokens) - n + 1)]

tokens = ['我', '爱', '自然语言', '处理']
print(generate_ngrams(tokens, 2))
# [('我', '爱'), ('爱', '自然语言'), ('自然语言', '处理')]
```

要点：
- 按**字**做 2-gram 时无需分词，中文场景下抗分词误差、缓解 OOV。
- 建议加边界符 `<s> </s>`，让首尾词也有完整上下文。
- 词级别 2-gram 与字级别 2-gram 可拼接使用。

### 三、batch 中句子长度不齐怎么处理

必须先把不等长序列规整成矩形张量，核心手段是 **padding + truncation + mask**。

**1. 填充（Padding）**

```python
from torch.nn.utils.rnn import pad_sequence
# 词表约定：<PAD>=0, <UNK>=1
padded = pad_sequence(seq_list, batch_first=True, padding_value=0)
# 或补到固定 max_len
```

- 补到 **batch 内最大长度**（动态，padding 最少）或补到 **固定 max_len**（稳定，便于 batch 间一致）。
- 填充值必须是词表中专门的 `<PAD>`，且设置 `padding_idx=0`（见 Q7）。

**2. 截断（Truncation）**

- 超长截断：保留尾部（结论常在句尾）或保留头部（标题/主题句），也可"头尾各留一半"。
- 截断长度取自长度分布分位数。

**3. 掩码（Masking）——关键，不能只 padding**

```python
lengths = torch.tensor([len(s) for s in seq_list])          # 真实长度，需降序排序
packed = pack_padded_sequence(emb, lengths, batch_first=True, enforce_sorted=False)
out, (h_n, c_n) = lstm(packed)
out, _ = pad_packed_sequence(out, batch_first=True)          # 还原为矩形
```

- `pack_padded_sequence` 让 LSTM **只在真实 token 上计算**，pad 不进入隐状态传递。
- 分类取句向量时，按真实长度 gather 最后一个有效时间步：

```python
idx = (lengths - 1).view(-1, 1, 1).expand(-1, 1, out.size(2))
last = out.gather(1, idx).squeeze(1)
```

- 做 pooling（mean/max）时，先按 mask 把 pad 位置置 `-inf`（max）或排除（mean），否则均值被 0 拉低。
- 损失计算用 `ignore_index=0`（pad 的 id），不把 pad 计入 loss。
- Transformer/Attention 用 `attention_mask` 屏蔽 pad 和（自回归时）未来位置。

**4. 排序分桶（Bucketing）**

按长度排序后组 batch，长度相近的句子在一起 → padding 量下降，训练更快；配合 `enforce_sorted=False` 可省去手动排序。

## Q3 LSTM 各门控与细胞状态的作用，相比 RNN 的优势与代价

### 一、LSTM 单元的前向公式

设 t 时刻输入 `x_t`，上一隐状态 `h_{t-1}`，上一细胞状态 `C_{t-1}`：

```
f_t = sigmoid(W_f · [h_{t-1}, x_t] + b_f)      # 遗忘门
i_t = sigmoid(W_i · [h_{t-1}, x_t] + b_i)      # 输入门
C~_t = tanh(W_C · [h_{t-1}, x_t] + b_C)        # 候选细胞状态
o_t = sigmoid(W_o · [h_{t-1}, x_t] + b_o)      # 输出门

C_t = f_t ⊙ C_{t-1} + i_t ⊙ C~_t               # 细胞状态更新
h_t = o_t ⊙ tanh(C_t)                          # 隐状态输出
```

### 二、各部分作用

| 组成部分 | 作用 |
| --- | --- |
| **遗忘门 f_t** | 决定旧记忆 `C_{t-1}` 中哪些维度被保留（→1）或丢弃（→0）。负责"选择性遗忘"，例如遇到新话题、段落结束、主语切换时清空旧信息。 |
| **输入门 i_t** | 决定候选新信息 `C~_t` 有多少写入细胞状态。负责"选择性记忆"，过滤掉无关词（如停用词、噪声）。 |
| **候选状态 C~_t** | 由当前输入与上一隐状态计算出的"待写入内容"，值域 (-1, 1)。 |
| **细胞状态 C_t** | **长期记忆的主干通道**。更新方式是**加性**（`f⊙C + i⊙C~`），梯度沿它传播时只需乘以 `f_t`（接近 1 时不衰减），近似"恒等映射"，这是 LSTM 缓解梯度消失的核心。 |
| **输出门 o_t** | 控制细胞状态中哪些信息暴露给外部隐状态 `h_t`，实现记忆与输出的解耦（记住的不一定要立刻说出来）。 |
| **隐状态 h_t** | 短期/工作记忆，直接用于下游预测。 |

一句话总结：**遗忘门管"丢什么"，输入门管"记什么"，细胞状态管"长期保存"，输出门管"输出什么"。**

### 三、相比普通 RNN 的优势

1. **缓解梯度消失**：RNN 的梯度含 `W^（t-k）` 连乘，易指数衰减；LSTM 靠细胞状态的加性恒等通路，梯度可远距离回传。
2. **能捕捉长距离依赖**：如主谓一致、指代、跨句情感转折。
3. **记忆可控**：门控可主动遗忘无关信息，减少噪声累积，对不相关上下文更鲁棒。
4. **训练更稳定**：配合梯度裁剪，实际调参难度低于朴素 RNN。

### 四、代价

1. **参数量约为 RNN 的 4 倍**（4 组 `W` 和 `b`），显存与内存占用更高。
2. **计算更慢**：每步要做 4 个矩阵变换 + 多次逐元素运算，训练/推理耗时明显高于 RNN 和 GRU。
3. **更易过拟合**：容量大 → 小数据上需要 dropout、weight decay、早停、预训练词向量。
4. **仍非万能**：超长序列（数百步以上）记忆依然衰减；时间步串行无法并行；仍可能被梯度爆炸影响（需 clip）。
5. **工程复杂度更高**：要正确处理 padding/mask/pack、初始状态、双向输出维度等（见 Q4、Q8）。

## Q4 双向 LSTM 与单向 LSTM 的区别、参数量变化、代码正确写法

### 一、核心区别

| 对比项 | 单向 LSTM | 双向 LSTM（BiLSTM） |
| --- | --- | --- |
| 信息流 | 仅正序（过去 → 现在） | 正序 + 逆序两条链 |
| `h_t` 依赖 | 只依赖 `x_1..x_t` | 同时依赖 `x_1..x_T`（前后文都可见） |
| 输出维度 | `(batch, seq, H)` | `(batch, seq, 2H)`，两个方向拼接 |
| 参数量 | 基准 | **约为单向的 2 倍** |
| 适用场景 | 自回归生成、语言模型、实时流式预测（只能用历史） | 文本分类、序列标注、NER、情感分析（可拿到完整序列） |
| 反向传播 | 沿时间反向传播（BPTT） | 正向层与反向层各自 BPTT，梯度再传向共同输入 |

典型应用：**BiLSTM + CRF** 是序列标注（分词、NER、词性标注）的经典方案。

### 二、参数量怎么变

设输入维度 `I`，隐层维度 `H`：

- 单向单层：`4 × (I·H + H·H + 2H)`（PyTorch 中偏置为 `4H` 形式，实际写作 `4(I·H + H·H) + 8H`）
- `bidirectional=True`：**每个方向一套独立权重**，参数量 ×2。
- `num_layers=L` 且双向时：第 2 层及以后的输入维度是 `2H`（上一层双向拼接结果），因此总参数并非简单 ×L，需逐层计算：

```
第 1 层：2 × 4(I·H + H·H + 2H)
第 k 层(k≥2)：2 × 4(2H·H + H·H + 2H)
```

- 输出特征维度始终是 `num_directions × H` = `2H`。

### 三、代码中的正确写法（PyTorch）

```python
import torch
import torch.nn as nn

I, H, L = 128, 256, 2          # 输入维度、隐层维度、层数
B, T = 32, 40                  # batch、序列长度
num_directions = 2             # bidirectional=True

lstm = nn.LSTM(
    input_size=I,
    hidden_size=H,
    num_layers=L,
    batch_first=True,
    bidirectional=True,
    dropout=0.2 if L > 1 else 0,   # 注意：dropout 仅在 num_layers > 1 时生效
)

x = torch.randn(B, T, I)

# 1) 初始状态维度：(num_layers * num_directions, batch, hidden_size)
h0 = torch.zeros(L * num_directions, B, H)
c0 = torch.zeros(L * num_directions, B, H)

# 2) 前向：LSTM 返回 (output, (h_n, c_n))
out, (h_n, c_n) = lstm(x, (h0, c0))
# out : (B, T, 2H)                   每个时间步：[正向 h, 反向 h] 拼接
# h_n : (L*2, B, H)                  各层各方向的最后一个时间步隐状态
# c_n : (L*2, B, H)

# 3) 取句向量的正确方式：重组 h_n → (L, 2, B, H)，取最后一层两个方向拼接
h_n_last = h_n.view(L, num_directions, B, H)[-1]     # (2, B, H)
sent_vec = torch.cat([h_n_last[0], h_n_last[1]], dim=-1)   # (B, 2H)

# 4) 接分类头（注意输入维度是 2H 而不是 H）
clf = nn.Linear(H * num_directions, num_classes)
logits = clf(sent_vec)
```

`h_n` 的排列顺序为：
```
[layer0_forward, layer0_backward, layer1_forward, layer1_backward, ...]
```

### 四、常见错误清单

1. **初始状态第一维写错**：双向时应为 `num_layers * num_directions`，写成 `num_layers` 会直接报 shape 错误。
2. **下游 Linear 维度忘乘 2**：输出是 `2H` 不是 `H`。
3. **用 `out[:, -1, :]` 当句向量**：
   - 双向时它等于 `[正向最后一步, 反向第一步]`，语义不对称；
   - 有 padding 时它取到的是 pad 位置的输出。
   - 正确做法：用 `h_n` 重组，或用真实长度 `gather`，或使用 `pack_padded_sequence`。
4. **混淆 `h_n` 与 `out[:, -1, :]`**：单层单向且无 padding 时二者相等；多层/双向/padding 时不相等。
5. **生成类任务误用双向**：解码时用双向会"看到未来"，造成标签泄漏。
6. **多层 dropout 位置**：`nn.LSTM(dropout=0.2)` 只作用于层间，不作用于最后一层输出。

## Q5 规则驱动 vs 数据驱动算法，传统算法 vs 机器学习算法各自关注什么

### 一、规则驱动（Rule-based）

**是什么**：由人总结规律，写成显式的规则、模板、词典、正则表达式、决策流程。

例子：关键词/敏感词匹配、正则抽取手机号邮箱、基于句法规则的成分分析、专家系统。

- **优点**：结果可控可解释、可精确修某个 bug、不需要标注数据、冷启动快、边界清晰场景（如格式校验）准确率极高。
- **缺点**：覆盖面有限、规则膨胀后互相冲突、维护成本高、无法泛化到未见过的形式、对语言多样性（口语、错别字、新词）极度脆弱。

### 二、数据驱动（Data-driven）

**是什么**：不给显式规则，让算法从大量样本中自动学习映射关系与参数。

例子：朴素贝叶斯、SVM、决策树、神经网络、预训练语言模型。

- **优点**：泛化能力强，能捕捉人难以总结的复杂模式；数据越多效果越好；跨领域迁移成本低（换数据重训即可）。
- **缺点**：依赖大量（常是标注）数据；可解释性差；会继承数据中的偏见与标注噪声；分布漂移时效果下降；调参与实验成本高。

### 三、两者关系

不是二选一，工业系统通常**混合使用**：

- 规则做**前置过滤**（如先正则抽时间实体）、**兜底**（模型低置信时走规则）、**后处理**（约束输出合法性，如 CRF 的转移约束、解码禁词表）。
- 模型负责主体判断，规则负责可解释性与安全边界。
- 也可用规则/远程监督**造数据**再训练模型，完成从规则驱动到数据驱动的迁移。

### 四、传统算法关注什么

| 关注点 | 说明 |
| --- | --- |
| 求解目标 | 在**明确定义的问题**上求出确定、正确的解 |
| 评价指标 | **时间复杂度、空间复杂度**、是否达到理论最优 |
| 正确性 | 可证明、可验证，输出确定（同输入必同输出） |
| 设计核心 | 数据结构选择、递推/分治/贪心/动态规划、剪枝、边界条件 |
| 典型问题 | 排序、最短路径、最大流、字符串匹配、背包问题 |
| 数据与逻辑 | 逻辑由人写死，数据只是输入 |

一句话：**传统算法关注"怎么算得又快又对"。**

### 五、机器学习算法关注什么

| 关注点 | 说明 |
| --- | --- |
| 求解目标 | 从数据中**估计**一个函数/分布，追求在**未见数据**上的表现（泛化） |
| 评价指标 | 测试集/验证集上的 **准确率、F1、AUC、RMSE** 等，以及泛化误差界 |
| 正确性 | 概率性、近似解，不保证最优，也不保证单样本正确 |
| 设计核心 | **偏差-方差权衡**、过拟合/欠拟合、特征工程与表示学习、损失函数、优化算法、模型容量 |
| 关键议题 | 正则化、交叉验证、数据划分与泄漏、类别不均衡、分布漂移、可解释性与公平性 |
| 数据与逻辑 | 逻辑由数据学出，数据质量决定效果上限 |

一句话：**机器学习算法关注"怎么在新数据上仍然好用"。**

### 六、一句话对照

- 传统算法：**输入 + 人写逻辑 → 确定输出**，追求**效率与最优性**。
- 机器学习：**输入 + 数据 → 学到逻辑 → 概率输出**，追求**泛化能力**。

## Q6 RNN、LSTM、GRU 的适用场景、选择建议、共同局限

### 一、三者结构差异

| 模型 | 门控 | 状态 | 参数量（相对） |
| --- | --- | --- | --- |
| RNN（Elman） | 无 | 只有 `h_t = tanh(W_ih·x_t + W_hh·h_{t-1})` | 1× |
| GRU | 更新门 `z_t`、重置门 `r_t`（2 个） | 只有 `h_t`（无独立细胞状态） | 约 3× |
| LSTM | 遗忘门、输入门、输出门（3 个）+ 候选状态 | `h_t` + `C_t`（独立细胞状态） | 约 4× |

### 二、适用场景

**RNN（Simple RNN）**
- 序列很短（十步以内）、依赖关系简单、资源极度受限。
- 教学/基线对照，用于展示梯度消失问题。
- 实际业务中基本不用作主模型。

**LSTM**
- **长序列**（几十到上百步）、**长距离依赖**明显的任务：机器翻译、文档级分类、长文本情感分析、序列标注。
- 数据量充足、追求效果上限、算力允许时优先选。
- 经典组合：BiLSTM、BiLSTM+CRF、Seq2Seq+Attention。

**GRU**
- 数据量不大、需要快速迭代训练、部署端对延迟/内存敏感。
- 中短序列任务：短文本分类、意图识别、情感分析、语音/时间序列。
- 在多数中小数据集上，GRU 与 LSTM 效果**相当甚至更好**（参数少 → 不易过拟合）。

### 三、选择建议（可直接背）

1. **先跑 GRU**：收敛快、参数少，用来快速验证可行性和拿基线。
2. **若欠拟合 / 序列很长 / 数据量大** → 换 LSTM，必要时上双向。
3. **若过拟合** → 说明容量过剩，退回 GRU，或加 dropout、用预训练词向量、减小 `hidden_size`。
4. **追求速度/上线** → GRU 优先（约省 25% 参数和计算）。
5. **序列标注** → BiLSTM（+CRF）。
6. **生成/解码** → 单向（双向会泄漏未来信息）。
7. **现代替代**：长文本与工业级场景已普遍转向 **Transformer / 预训练模型（BERT、RoBERTa）**；RNN 系更多用于轻量、流式、低延迟场景。

### 四、共同局限

1. **串行计算，无法并行**：时间步必须逐步推进，长序列训练/推理慢，GPU 利用率低。
2. **长程依赖仍会衰减**：LSTM/GRU 只是**缓解**而非根除梯度消失，有效记忆窗口通常只有几十到一两百步，超长依赖仍丢失。
3. **梯度爆炸风险仍在**：需要梯度裁剪（`clip_grad_norm_`）。
4. **信息瓶颈**：全部历史被压进固定维度的隐向量，序列越长压缩越严重。
5. **padding 与长度处理繁琐**：不等长需 mask/pack/pooling，长度差异大时算力浪费明显。
6. **难以规模化预训练**：无法像 Transformer 那样在超大规模语料上高效并行预训练，因此表示能力上限低于预训练语言模型。
7. **可解释性有限**，且对超参（层数、`hidden_size`、dropout、学习率、初始化）较敏感。
8. **位置/结构感知弱**：只靠顺序递推建模位置，缺少显式的全局结构建模。

## Q7 嵌入层 `padding_idx=0` 的作用，不设置会怎样

### 一、作用

```python
emb = nn.Embedding(num_embeddings=vocab_size,
                   embedding_dim=300,
                   padding_idx=0)   # 0 号是 <PAD>
```

设置后发生三件事：

1. **该行向量初始化为全 0**，而不是随机初始化。
2. **训练时该行的梯度被强制置零**，因此它**始终保持全 0**，不会随训练漂移。
3. 语义上明确"0 号不是词，是填充占位符"。

带来的好处：

- 填充位置送入 RNN/LSTM/Attention 时**不携带任何语义信息**，不会污染隐状态。
- 做 mean pooling 时，pad 的 0 向量理论上不贡献方向（但仍会拉低均值绝对值 → 仍需 mask）。
- 配合 `pack_padded_sequence`、`attention_mask`、`CrossEntropyLoss(ignore_index=0)` 使用，能真正把 pad 从计算与损失中剔除。

### 二、如果不设置 `padding_idx` 会怎样

**情形 1：设了 pad 但没设 `padding_idx`**

- `<PAD>` 被当成**一个普通词**：随机初始化，并且**会随训练不断更新**。
- 后果：
  - 每个 batch 的 pad 数量不同 → 不同数量的"噪声向量"进入 RNN，隐状态被污染，输出与句子长度/批内长度产生**虚假相关性**。
  - 池化/注意力结果被这个学出来的奇怪向量扭曲，模型泛化变差。
  - 该向量还可能学到与任务相关的偏移，导致推理时结果依赖 padding 多少，很不稳健。

**情形 2：完全不做 padding**

- batch 内句子长度不齐，**无法拼成规整张量**，矩阵运算无法进行。
- 只能 `batch_size=1` 逐条训练（极慢，且梯度不稳定），因此**批处理场景下 padding 是必需的**。

### 三、配套注意事项（易混点）

1. **词表构造时把 `<PAD>` 放在索引 0**，并让 `<UNK>` 等其它特殊符号顺延（如 `<UNK>=1`），确保 pad 的 id 不与真实词冲突。
2. **只设 `padding_idx` 还不够**：LSTM 仍会把 pad 步当成真实输入计算（只是输入是 0 向量），仍会更新隐状态。要彻底屏蔽，必须：
   - 用 `pack_padded_sequence`；或
   - 用真实长度 gather 最后一个有效步；或
   - 用 mask 做池化。
3. **损失侧**：`nn.CrossEntropyLoss(ignore_index=0)`，别让 pad 参与 loss 与指标计算。
4. **评估侧**：计算准确率/F1 时同样要排除 pad 位置（序列标注任务常见坑）。
5. `padding_idx` 可以是任意合法索引，但**业界约定用 0**，这样与默认填充值、多数工具链一致。

## Q8 RNN、LSTM、GRU 在 API 返回值上的区别，LSTM 容易写错的地方

### 一、PyTorch API 返回值对比

```python
rnn  = nn.RNN(input_size=I, hidden_size=H, batch_first=True)
gru  = nn.GRU(input_size=I, hidden_size=H, batch_first=True)
lstm = nn.LSTM(input_size=I, hidden_size=H, batch_first=True)

out,  h_n        = rnn(x,  h0)          # RNN：返回 (output, h_n)
out,  h_n        = gru(x,  h0)          # GRU：返回 (output, h_n)
out, (h_n, c_n)  = lstm(x, (h0, c0))    # LSTM：返回 (output, (h_n, c_n))
```

| 对比项 | nn.RNN | nn.GRU | nn.LSTM |
| --- | --- | --- | --- |
| 返回值个数 | 2（`out, h_n`） | 2（`out, h_n`） | 2，但第二项是**元组** `(h_n, c_n)` |
| 初始状态 | 单个 `h0` | 单个 `h0` | **元组** `(h0, c0)` |
| 是否有细胞状态 | 无 | 无 | **有 `c_n`** |
| `out` 形状 | `(B, T, D*H)` | `(B, T, D*H)` | `(B, T, D*H)` |
| `h_n` 形状 | `(L*D, B, H)` | `(L*D, B, H)` | `(L*D, B, H)` |
| `c_n` 形状 | — | — | `(L*D, B, H)` |

（`B`=batch，`T`=seq_len，`L`=num_layers，`D`=num_directions，`H`=hidden_size）

- 三者**不传初始状态时默认全 0**，因此 `(h0, c0)` 可以省略。
- `out` 是**所有时间步**最后一层的输出；`h_n` 是**最后一个时间步所有层**的隐状态。
- Keras/TensorFlow 对应：`SimpleRNN`/`GRU` 返回 `output` 或 `(output, state)`；`LSTM` 返回 `(output, h, c)`，由 `return_sequences`、`return_state` 控制。

### 二、LSTM 容易写错的地方（重点）

1. **忘了解包元组**
   ```python
   out, h = lstm(x)      # ValueError: too many values to unpack
   out, (h_n, c_n) = lstm(x)   # 正确
   ```

2. **传初始状态时写成单个张量**
   ```python
   lstm(x, h0)      # 错误
   lstm(x, (h0, c0))   # 正确
   ```

3. **状态维度写错**：应为 `(num_layers * num_directions, batch, hidden_size)`，常误写成 `(batch, seq, H)` 或把 `batch` 与层数顺序颠倒。

4. **双向时维度漏乘 2**：`h0` 第一维应为 `L*2`；输出最后一维是 `2H`，接 `nn.Linear` 时输入要写 `H * 2`。

5. **用 `out[:, -1, :]` 当句向量（最经典的错误）**
   - 有 padding 时取到的是 **pad 位置**的输出；
   - 双向时它是 `[正向最后一步, 反向第一步]`，语义不对称；
   - 多层时它只是**最后一层**的输出。
   - 正确做法：
     ```python
     # 方式 A：用 h_n（需无 padding，或用 pack 后）
     h_n_last = h_n.view(L, D, B, H)[-1]
     vec = torch.cat([h_n_last[0], h_n_last[1]], dim=-1)

     # 方式 B：按真实长度 gather
     idx = (lengths - 1).view(-1, 1, 1).expand(-1, 1, out.size(2))
     vec = out.gather(1, idx).squeeze(1)
     ```

6. **混淆 `h_n` 与 `c_n`**：做句向量/分类特征通常用 `h_n`（对外输出），`c_n` 是内部记忆，直接当特征往往效果更差。

7. **多层时输入维度算错**：PyTorch 内部会自动把上一层输出（维度 `D*H`）接到下一层，但自己接 `Linear`、写 `hidden_size`、做残差/拼接时必须手动按 `D*H` 计算。

8. **pooling 前不 mask**：mean pooling 会把 pad 的 0 向量计入分母，句向量被"稀释"；max pooling 需把 pad 位置置 `-inf`。

9. **手写循环时忘 `detach`**：自回归生成中把 `h` 一直带着计算图往前传，会导致显存暴涨；状态也容易跨 batch 泄漏，每个 batch 应重置。

10. **`dropout` 参数误用**：`nn.LSTM(dropout=0.5)` 只在 `num_layers > 1` 时生效，单层设置无效（会收到警告）。

11. **把 `batch_first` 忘了统一**：设置 `batch_first=True` 后所有输入输出都是 `(B, T, ...)`，但 `h_n`/`c_n` **始终是** `(L*D, B, H)`，不受 `batch_first` 影响——这一点极容易搞混。

12. **Embedding 与 LSTM 的 pad 处理脱节**：只设 `padding_idx` 不足以屏蔽 pad，必须配合 pack/mask（见 Q7）。
